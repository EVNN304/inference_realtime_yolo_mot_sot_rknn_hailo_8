# GIMB — детекция и трекинг на встраиваемой платформе

Проект объединяет YOLO, HybridSORT и NanoTrack на Orange Pi 5 / RK3588 с ускорителем Hailo-8. Основная инженерная работа — интеграция ускорителей в общий поток обработки: батчинг, асинхронные задания, управление буферами, сохранение timestamps и передача целей от MOT к SOT.

## Что можно выбрать в конфигурации

| Настройка | Назначение |
|---|---|
| `detector_backend` | YOLO на `hailo` или `rknn` |
| `mot_backend` | OSNet на `hailo` или `rknn`; сопоставление HybridSORT остаётся на CPU |
| `Detector.use_sahi` | Полный кадр или тайлинг |
| `Hailo.full_frame_batch` | Число разных кадров в батче полного кадра |
| `Hailo.sahi_batch` | Число тайлов в батче |
| `Hailo.inflight` | Число слотов асинхронного инференса |

Режим RKNN/RKNN использует прежний цикл детекции. При выборе Hailo включается адаптер, который сохраняет интерфейс взаимодействия с контроллером трекинга.

## Запуск

1. Установить системные зависимости и SDK по [инструкции](SETUP.md).
2. Подготовить свои HEF/RKNN/ONNX модели. Веса в архив не включены.
3. Скопировать `config/local.example.py` в `config/local.py` и указать реальные пути.
4. Запустить из корня проекта:

```bash
python -m src.gimb
```

Каталог приложения теперь называется `src/gimb`. Основная конфигурация находится в `config/config.py`. Персональные значения задаются в `config/local.py`, который исключён из Git.

## Что подтверждено измерениями

Отдельный бенчмарк YOLO11s HEF показал около 52 FPS. В приложении после исправления подачи кадров детектор показал примерно 28–30,7 FPS при источнике 29,97 FPS. Это разные измерения: второй тест ограничен скоростью видео и не доказывает работу всего приложения на 50–60 FPS. Подробности — в [описании результатов](PERFORMANCE.md).

## Последние изменения

- Новые кадры берутся из кольцевого буфера по порядку, включая пришедшие во время подготовки предыдущего батча.
- Давность буфера ограничена, чтобы длительный сбой не превращался в постоянно растущую задержку.
- Видеофайл воспроизводится по часам источника с учётом времени декодирования.
- FPS YOLO/MOT считается по завершённым результатам, а не как обратная величина задержки батча.
- Добавлены отдельные замеры подготовки, ожидания устройства, callback и получения результатов.
- Переименовано приложение и обновлены импорты; пути NanoTrack перенесены в конфигурацию.

Следующий этап проверки — фактическая скорость детектора с камерой 60 FPS. Скорость MOT и стабильность ID оцениваются отдельно.
